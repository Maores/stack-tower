# Revive Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One paid comeback per run: die, pay 150 points, resume the same tower, keep climbing.

**Architecture:** `core.js` gains one new capability, resuming a dead run, requested over a CustomEvent and guarded by a per-run flag. `hud.js` gains a second circle in the death screen's action row that arms on one tap and pays on the next, plus a two-showing death screen where the first death commits everything exactly as it does today and the second commits only the bonus lap's points. No backend change, no schema change, no new network call.

**Tech Stack:** Vanilla ES5 browser JS in three cooperating files (`core.js`, `hud.js`, `hud.css`), Three.js for the scene, Playwright for verification. No build step except `node scripts/build-offline.mjs`, which inlines everything into `Stack.html`.

**Spec:** `docs/superpowers/specs/2026-08-06-revive-design.md` (committed f6b39c6). Read it before Task 1.

## Global Constraints

Every task's requirements implicitly include all of these.

- **`hud.js` is ES5.** `var` only, IIFE scope, defensive `try/catch` around storage, `textContent` only, never `innerHTML` for user data.
- **Cross-domain coupling is CustomEvents only.** `hud.js` must never call into `core.js` internals, and vice versa.
- **Game UI text stays English.** Hebrew player names are data and keep their LRM guard in roast templates.
- **Minimum tap target is 44px.** The revive control is 64px plus a 12px invisible expander.
- **The revive control must be a real `<button>`**, because `core.js` binds a global tap-to-restart on `window` and skips only `button, a, input, [data-ui]`.
- **Its selector must also be added to `tryRestart`'s exclusion list** in `hud.js`, which today reads `.hud-lb-entry, .hud-lb-auto, .hud-over-menu`.
- **`CFG.restartLockMs` (450ms) must NOT gate a revive request.** Deliberate; see spec.
- **Shared board takes pre-revive height only.** Non-negotiable, and Task 6 is the test that guards it.
- **Rebuild `Stack.html`** with `node scripts/build-offline.mjs` in any commit that touches `core.js`, `hud.js` or `hud.css`.
- **Scripted tests need `?debug=1`.** Without it `StackCore.debug` is a decoy.
- **Any test that can reach the save flow must intercept `**/rest/v1/stack_scores*`** so no real rows land.
- **Constants, exact values:** price `150`, offer threshold `10`, arm window `3000ms` (reuse `SHOP_ARM_MS`), revive entrance delay `0.14s`.

| File | Responsibility this wave |
|---|---|
| `core.js` | The resume capability: `hud:revive` listener, per-run `revived` flag, width restore per mode, phase return to `playing`, `game:revived` emit |

```js
/* Revive: core resumes a dead run once, and Normal alone gets width back.

   Uses only the debug API that exists: drop(offset), build(n, offset),
   mode(). There is no playTo or kill. A run is driven with build() and ended
   with drop(99), whose offset is far past any overlap, so it is a total miss.
   SLICE is deliberately just above CFG.perfectEps (0.14): at or under it every
   drop snaps as a perfect and the footprint never shrinks, which would make
   the width assertions pass for the wrong reason. */
const { chromium, devices } = require('playwright');
const path = require('node:path');
const { startServer } = require('./lib/serve');

const ROOT = path.resolve(__dirname, '..', '..');
const LIVE = !!process.env.STACK_LIVE;
const SLICE = 0.16;
const LOCKOUT_MS = 600;   /* > hud RESTART_LOCKOUT_MS (500) and core's 450 */

function fail(msg, data) { throw new Error('FAIL ' + msg + ': ' + JSON.stringify(data)); }

async function freshPage(ctx, base, seed) {
  const page = await ctx.newPage();
  await page.addInitScript((s) => {
    try {
      localStorage.setItem('stack-points', String(s.points));
      localStorage.setItem('stack-best', String(s.best));
      if (s.name) { localStorage.setItem('stack-player-name', s.name); }
    } catch (e) { /* ignore */ }
  }, seed);
  await page.goto(base + '?debug=1');
  await page.waitForFunction(() =>
    window.StackCore && window.StackCore.debug && window.StackCore.debug.drop);
  return page;
}

async function toDeath(page, blocks) {
  await page.evaluate((a) => {
    const d = window.StackCore.debug;
    d.build(a.blocks, a.slice);
    d.drop(99);
  }, { blocks: blocks, slice: SLICE });
  await page.waitForFunction(() =>
    document.querySelector('#hud-root').dataset.state === 'over');
}

(async () => {
  const server = LIVE ? null : await startServer(ROOT);
  const base = LIVE ? 'https://maores.github.io/stack-tower/' : server.url;
  const browser = await chromium.launch();
  const ctx = await browser.newContext({ ...devices['iPhone 13'] });
  const posts = [];
  await ctx.route('**/rest/v1/stack_scores*', (route) => {
    const req = route.request();
    if (req.method() === 'POST') {
      try { posts.push(JSON.parse(req.postData() || '{}')); } catch (e) { posts.push({}); }
      return route.fulfill({ status: 201, contentType: 'application/json', body: '[]' });
    }
    return route.continue();
  });

  /* --- A. core resumes once, and Normal restores the footprint --- */
  const page = await freshPage(ctx, base, { points: 400, best: 5 });
  const errs = [];
  page.on('pageerror', (e) => errs.push(String(e)));

  const dead = await page.evaluate((slice) => {
    const d = window.StackCore.debug;
    d.build(12, slice);
    d.drop(99);
    return d.revive();
  }, SLICE);
  if (dead.phase !== 'gameover') { fail('run did not end', dead); }
  if (dead.revived !== false) { fail('flag set before revive', dead); }
  if (!(dead.width < 2.5)) { fail('footprint was not ground down', dead); }

  const alive = await page.evaluate(() => {
    window.dispatchEvent(new CustomEvent('hud:revive'));
    return window.StackCore.debug.revive();
  });
  if (alive.phase !== 'playing') { fail('revive did not resume', alive); }
  if (alive.revived !== true) { fail('flag not set', alive); }
  if (Math.abs(alive.width - 2.6) > 0.001) { fail('Normal did not restore width', alive); }

  const twice = await page.evaluate(() => {
    const d = window.StackCore.debug;
    d.drop(99);
    window.dispatchEvent(new CustomEvent('hud:revive'));
    return d.revive();
  });
  if (twice.phase !== 'gameover') { fail('a second revive was granted', twice); }

  if (errs.length) { fail('page errors', errs); }
  console.log('PASS pw-revive A: core resume');
  await page.close();

  await browser.close();
  if (server) { await server.close(); }
})().catch((e) => { console.error(String(e)); process.exit(1); });
```

Add the resume function next to `restartGame()`:

```js
  /* Resume a dead run in place: the fatal block is gone, the tower stands.
     Normal gives the footprint back in full; Hard never restores width, which
     is the one rule that defines the mode (retention spec), so it resumes on
     the sliver it died on. Speed is untouched either way: it is derived from
     block index in spawnNext, so the run continues at the pace it reached. */
  function reviveRun() {
    if (phase !== 'gameover' || revivedThisRun) { return; }
    revivedThisRun = true;
    phase = 'playing';
    phaseStartedAt = performance.now();
    if (MODES[activeMode] && MODES[activeMode].regrow) {
      var top = topBlock();
      top.w = CFG.blockSize;
      top.d = CFG.blockSize;
    }
    camTargetViewH = CFG.viewHeight;
    fireDom('game:revived', { score: score, mode: activeMode });
    emit('revive', { state: getTowerState() });
    spawnNext();
  }
```

Note on the width restore: `spawnNext()` reads `prev.w` / `prev.d` from `topBlock()`, so widening the record is what widens the next block. The placed mesh is not resized, deliberately: the tower keeps the silhouette it earned and the wide block lands on the narrow neck.

Register the listener in `bindInput()`, beside the `hud:menu` one:

```js
    /* Paid comeback. No restartLockMs gate here on purpose: the lock exists so
       the gesture that killed you cannot restart the run, and the revive is
       already guarded by two deliberate taps on a real button that only
       appears at 0.14s. Gating it as well would refuse a fast arm-and-confirm
       and read as a dead button. */
    window.addEventListener('hud:revive', function () { reviveRun(); });
```

- [ ] **Step 1: Add the render and arm helpers**

In `hud.js`, near the shop's `disarmShop`:

```js
  /* Two-tap purchase, the same shape the shop uses for a World: the first tap
     arms, the second inside the window pays. A stray tap can therefore cost
     nothing, which matters more here than in the shop because the free
     restart button is 26px away. */
  var reviveArm = { on: false, timer: null };

  function disarmRevive() {
    if (reviveArm.timer) { clearTimeout(reviveArm.timer); }
    reviveArm.timer = null;
    if (!reviveArm.on) { return; }
    reviveArm.on = false;
    if (!els) { return; }
    els.revive.classList.remove('is-armed');
    els.reviveCap.classList.remove('is-hot');
    els.reviveCap.textContent = 'REVIVE · ' + REVIVE_COST;
    els.overHint.textContent = 'TAP TO RESTART';
  }

  /* The offer is shown from score 10 up, in both modes, and dimmed rather than
     hidden when the balance is short: a player who has never held 150 points
     still learns the feature exists and what to save for. Below the threshold
     there is no control at all and the screen is byte-for-byte today's. */
  function renderRevive(score, mode) {
    if (!els) { return; }
    disarmRevive();
    var offer = score >= REVIVE_MIN_SCORE && !state.revived;
    els.reviveWrap.hidden = !offer;
    if (!offer) { return; }
    var broke = readInt(PTS_KEY) < REVIVE_COST;
    els.revive.classList.toggle('is-broke', broke);
    els.revive.disabled = broke;
    els.reviveCap.textContent = 'REVIVE · ' + REVIVE_COST;
    els.revive.setAttribute('aria-label',
      'Revive for ' + REVIVE_COST + ' points' + (broke ? ', not enough points' : ''));
  }
```
